# Hybrid Macro Desk — セットアップコンソール 実装指示書 v1.0

## 0. 最初に読むこと（この指示書の性格）

このコンソールは **トレードを実行しない**。判断もしない。やることは3つだけ：

1. 人間が決めたルールに従って **算術を検算し、違反を赤く表示する**
2. POI到達時に **吸収コンファームを機械判定し、「置いてある指値を残してよいか／引くべきか」だけを出す**
3. 到達・判定・結果を **台帳に記録する**

設計思想は「拒否権」。緑のランプは「入れ」ではなく「消さなくてよい」。この向きを UI の文言・色・レイアウトのすべてで守ること。「エントリーシグナル」「買い時」「売り時」という語は UI に一切出さない。

参照元となる人間側の文書（内容は本指示書に転記済み。矛盾があれば本指示書を正とする）：
- 運用規程 v0.3.3（A4 PDF）
- 吸収コンファーム Pine v0.3.3（TradingView）
- 校正シート v0.2 / POI水準台帳 v3（Google Sheets）

## 2. データソースと共通規約

### 2.1 価格データ
- **計測市場は Binance USDⓈ-M 先物 `BTCUSDT`**（執行は Hyperliquid だが、校正は Binance データで行われている。混ぜない）
- REST: `GET /fapi/v1/klines`（`interval=1m` および `15m`、`1h`）。kline の `takerBuyBaseVolume` フィールドを取得すること
- ライブ更新: WebSocket `btcusdt@kline_15m` / `btcusdt@kline_1m`（v1 は REST ポーリング 15 秒でも可。確定足のみ扱うため遅延は許容）

### 2.2 タイムゾーン
- 内部は UTC、**表示・記録・入力はすべて Europe/Paris（CEST/CET）**
- 15分足の確定時刻は Binance の足の close 時刻を Europe/Paris に変換して表示（例: 23:30 の足＝23:30–23:44:59、確定表示は 23:45）
- 記録ファイルのタイムスタンプ列は `YYYY-MM-DD HH:MM` の Europe/Paris 表記＋別列に UTC epoch

### 2.3 ATR
- `ATR(14)` は TradingView の `ta.atr` と同じ **RMA（Wilder）平滑**。EMA でも SMA でもない。ユニットテストで TradingView 表示値と ±1% 以内で一致させること（校正シートの ATR 列が正解データ）
- 15分ATR は判定用、1時間ATR は SL 設計用。**混ぜない**（UI で常に「15m ATR」「1H ATR」とラベル付け）

### 2.4 デルタ（最重要）
足ごとのデルタ δ を2方式で計算し、設定で切替可能にする：

| 方式 | 計算 | 用途 |
|---|---|---|
| `taker`（既定） | δ = 2 × takerBuyBaseVolume − volume（15分足 kline 自体の値） | 真の攻め手側。ネイティブフットプリントに最も近い |
| `reconstruct` | 1分足を15本集約: 各1分足で close>open なら +vol、close<open なら −vol、同値は 0。合計 | Pine v0.3.3 と同一（検証・比較用） |

受け入れ条件: 3つの校正場面（§7）で両方式の Σδ が **符号一致かつ絶対値が校正シート値の ±30% 以内**。外れる場合は理由を報告して停止（閾値を勝手に調整しない）。

### 2.5 設定の管理
- 閾値は `config/confirm_v0.3.3.json` に固定。ファイル名にバージョンを含める
- UI に現行バージョンを常時表示
- 閾値変更＝新ファイル追加＋バージョン表示更新。既存ファイルの上書き禁止

```json
{
  "version": "v0.3.3",
  "timeframe": "15m",
  "window_bars": 3,
  "x_ratio": 0.05,
  "atr_coef": 0.75,
  "atr_len": 14,
  "vol_floor_mult": 3.0,
  "vol_median_len": 96,
  "accept_consecutive": 2,
  "delta_method": "taker"
}
```

## 4. モジュール B：算術（Arithmetic）

入力（UI フォーム）: 残高 USD、リスク%（既定 2、勝ちトレード後は 1）、方向、エントリー（単発 or 2〜3分割の価格とロット比率）、SL、TP、1H ATR、清算帯（上側／下側の価格）。

出力と違反フラグ：

| 項目 | 式 | 違反条件（赤） |
|---|---|---|
| SL幅 | \|平均エントリー − SL\| | SL幅 < 2 × 1H ATR |
| SL位置 | — | SL が指定した清算帯の **内側** |
| TP位置 | — | TP が次の清算帯を **越えている** |
| R:R | \|TP − 平均エントリー\| ÷ SL幅 | R:R < 2.0 |
| 最大ロット | (残高 × リスク%) ÷ SL幅 | 入力ロット > 最大ロット |
| 分散 | 帯の厚み | 厚み < 2 × 15m ATR なのに分割指定 |
| 全約定時リスク | Σ(枠ロット) × SL幅 | > 残高 × リスク% |
| 週末ATR | — | 土日・米休場日に「直近フル流動性セッションのATRを使用」の警告を出し、当日ATRの使用を赤字で拒否 |
| 名目・レバレッジ | ロット × 価格 ÷ 残高 | 表示のみ |

フラグが1つでも赤なら「敷設不可」バッジ。**設計値を勝手に丸めたり補正したりしない**（人間が直す）。

## 5. モジュール C：吸収コンファーム（Confirm Engine）

Pine v0.3.3 の完全移植。**ロジックは一文字も変えない。**

### 5.1 入力（到達ごとに1回設定。平時に次の帯の値を先に入れる）
- `mode`: "S" | "L" | "both"
- `ref_s`, `ref_l`: 参照水準（0 で (c) 無効）。帯 POI は帯の向こう側の縁
- `zone_lo`, `zone_hi`, `use_zone`: 表示フィルタ（判定には影響しない）

### 5.2 15分確定足ごとの計算（直近3本の窓）
```
Σδ = δ[0] + δ[1] + δ[2]                      // [0]=最新確定足
ΣV = V[0] + V[1] + V[2]
ratio = |Σδ| / ΣV
floor_ok = ΣV >= vol_floor_mult × median(V, vol_median_len)
atr = ATR14_15m[0]

S側:
  dir_ok = Σδ > 0
  prog   = max(H[0],H[1],H[2]) − H[2]
  a = ratio >= x_ratio AND dir_ok AND floor_ok
  b = prog < atr_coef × atr
  c = (ref_s == 0) OR (C[0] < ref_s)
  d = δ[2] > 0
L側:
  dir_ok = Σδ < 0
  prog   = L[2] − min(L[0],L[1],L[2])
  a, b 同様
  c = (ref_l == 0) OR (C[0] > ref_l)
  d = δ[2] < 0

verdict:
  fire     = a AND b AND c AND d           → "成立"
  rejected = a AND b AND d AND NOT c       → "(c)棄却"
  else                                     → "沈黙"
```

### 5.3 受け入れ警告（描画・通知用。判定とは独立）
```
S: 確定足の C > ref_s が accept_consecutive 本連続 → その N 本目で1回だけ "受け入れ↑ 整理準備"
L: 確定足の C < ref_l が N 本連続 → "受け入れ↓ 整理準備"
連続が途切れたらカウンタを 0 に戻す
```

### 5.4 出力
- **診断表**（Pine と同じ行構成）: Σδ／ΣV／攻め比率／床／向き整合／前進÷ATR／(c)位置／(d)1本目／受け入れカウント／判定（S側・L側）
- **履歴**: 各確定足の verdict を時系列で保存（成立・棄却・沈黙すべて。沈黙も保存する）
- 形成中の足では判定を出さない。診断表の数値だけ「暫定」ラベル付きでリアルタイム表示可

### 5.5 UI 文言の固定
- 成立 → 「指値を残してよい」
- (c)棄却 → 「向こう側で受け入れ。プロトコル③へ」
- 受け入れ警告 → 「整理準備。プロトコル③へ」
- 沈黙 → 「—」
- 使ってはいけない語: シグナル、エントリー推奨、ロング/ショート推奨、Buy/Sell

### 5.6 既知の限界（UI の説明欄に明記）
- 点灯は極値の 2〜3 本後（30〜45 分）。追いかける道具ではない
- 守備範囲は「攻め手の失敗（吸収）」のみ。売り主導の反転や素直なブレイク継続は拾わない
- 閾値は 15 分足で校正されたセット。他の時間足への流用禁止

## 6. モジュール D：執行フロー（ステートマシン）

既存 Entry Console の `IDLE→ARMED→PULLBACK→TRIGGERED` を置き換えず、**別のステートマシンとして並置**する（旧エンジンは残す）。

```
IDLE
  └─(算術OK かつ カレンダーゲート開)→ PLACED        // 敷設済み（人間が手動で発注し、チェック）
PLACED
  ├─(価格が帯に到達)→ AT_POI
  ├─(イベント窓に入る)→ PULLED_EVENT              // 未約定を撤去（人間が実施、チェック）
  └─(金曜引け)→ PULLED_WEEKEND
AT_POI
  ├─(成立)→ CONFIRMED                             // 未約定を残す
  ├─((c)棄却 OR 受け入れ警告)→ REJECTED           // 未約定撤去
  ├─(不成立のまま帯離脱)→ REJECTED
  └─(約定通知＝人間が入力)→ FILLED_UNCONFIRMED
FILLED_UNCONFIRMED                                // プロトコル①〜④
  ├─ SL固定（表示・変更不可）
  ├─(成立)→ MANAGE
  ├─((c)棄却 OR 受け入れ警告)→ EXIT_PLAN          // 建値±0.25×ATRの撤退指値を提示、1H時間スクラッチのタイマー
  └─(4窓経過で成立も棄却もなし)→ EXIT_PLAN（時間スクラッチ）
MANAGE → CLOSED
```

各遷移は **人間のチェック操作**で進む（自動遷移は「価格が帯に到達」「窓のカウント」「タイマー」のみ）。UI は各状態で「いま人間がやること」を1行で表示する：
- PLACED: 「指値は帯・SL・ロットの算術値で敷設済みか」
- AT_POI: 「15分の確定ごとに判定を見る。形成中は見ない」
- REJECTED: 「未約定を全部引く」
- FILLED_UNCONFIRMED: 「SLは動かさない。枠を足さない」
- EXIT_PLAN: 「次の戻りで建値±0.25×ATR。戻らなければ時間スクラッチ、最悪SL」
